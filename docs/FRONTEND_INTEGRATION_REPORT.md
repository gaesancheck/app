# PawStep 프런트엔드 API 연동 결과

검증일: 2026-11-06. 기준 문서는 제공된 `pawstep-backend/docs/FRONTEND_INTEGRATION_PRD.md`, `docs/API_SPEC.md`, `backend/README.md`의 Decisions다. 백엔드 소스는 수정하지 않았다. 기존 사용자의 지도·UI·README 변경은 커밋에 포함하지 않았다.

## 2. E2E 시나리오 결과

실제 API 서버와 Python 경로 엔진을 실행했다. 앱은 `EXPO_PUBLIC_USE_MOCK=false`, `EXPO_PUBLIC_API_BASE_URL=http://192.168.0.105:8080`을 사용했다. 백엔드 `PUBLIC_BASE_URL`도 같은 LAN 주소로 설정하여 이미지 URL에 localhost가 들어가지 않게 했다. 이 설정과 JWT 비밀값은 로컬에만 보관했다.

검증 방법을 구분한다.

- **HTTP 검증:** 실행 중인 서버에 실제 요청을 보내 상태·본문·저장 결과를 확인했다.
- **iOS 검증:** iPhone 18 Pro / iOS 27.2 시뮬레이터의 기존 개발 빌드에 현재 Metro 번들을 연결했다. Hermes 디버거에서 앱이 실제 사용하는 API 어댑터를 실행했다. Expo File로 만든 기기 파일의 실제 multipart 업로드, SecureStore 저장·삭제, Expo Router 이동을 포함한다.
- **화면 확인:** 개발 로그인 버튼의 실제 onPress를 실행하여 온보딩 이동을 확인했다. 보호동물 목록과 탈퇴 후 로그인 화면도 확인했다.
- **한계:** 모든 화면의 입력·선택·버튼을 터치로 순회하는 완전한 UI E2E는 실행하지 않았다. Android·실기기·새 네이티브 바이너리 빌드도 확인하지 않았다. 아래 통과는 실제 백엔드와 iOS 앱 어댑터 기준이다.

| 번호 | 시나리오 | HTTP | iOS 앱 어댑터 | 확인 내용·제약 |
| --- | --- | --- | --- | --- |
| 1 | 개발 로그인·온보딩 | 통과 | 통과 | `needs_onboarding: true`, 초기 `petInfo: null`, 완료 후 서버 반려견 생성. 개발 로그인→온보딩 화면 이동 확인 |
| 2 | 사진·반려견 수정·추가·삭제 | 통과 | 통과 | 실제 기기 File 업로드→HTTP URL, 사진 수정, 둘째 반려견 추가·삭제, `YYYYMMDD`→`MM.DD` 변환 |
| 3 | 필터 2개·대안 경로 | 통과 | 통과 | 다른 코스 필터와 대안 요청, 경로 차이 확인. HTTP에서는 위치 좌표 명시, 엔진 `source: planner` 확인. iOS는 시뮬레이터 위치 설정 후 호출 |
| 4 | 산책 기록 CRUD | 통과 | 통과 | POST 응답의 서버 ID, 목록·상세·수정·삭제, 사진 URL. 삭제 204 본문 없음 |
| 5 | 사진 게시물·좋아요·댓글·삭제 | 통과 | 통과 | 사진 업로드, `heart: true` 반복 시 좋아요 1, 갱신된 Post 댓글, 목록 댓글 수, 게시물 삭제 |
| 6 | A 실종·B 제보·양방향 채팅·해제 | 통과 | 통과 | 계정별 세션 전환, 제보 사진 업로드, 받은 제보·메시지 조회, 서버 ID로 발신자 구분, 체크리스트 저장, 해제 후 연동 게시물 제거. 실종 중 반려견·연동 게시물 삭제 409 확인 |
| 7 | 보호동물 목록 | 통과 | 통과 | 실제 서버 응답과 화면 표시 확인. 공공데이터 키가 없어 **백엔드 샘플 fallback** 사용 |
| 8 | 탈퇴·기존 토큰 401·로그인 이동 | 통과 | 통과 | 탈퇴 204, 같은 토큰 요청 401, SecureStore 세션 null, 로컬 정리, 로그인 화면 렌더 확인 |

추가 확인: 문의 생성 204 후 목록 재조회, 게시물 페이지 `20 + 1` 조회, 업로드 URL의 LAN 접근, 409 안내. 임시 검증 계정의 주 시나리오 데이터는 계정 탈퇴로 정리했다.

요청에서 별도로 지정한 백엔드 초기 `npm test`는 **21/21 통과**했다. 일반 프런트 테스트는 AGENTS 지침에 따라 추가·실행하지 않았다. `npx tsc --noEmit` 및 `git diff --check`를 확인했고, iOS Metro 번들 로딩도 성공했다. 읽기 전용 리뷰 후 보고된 중요 문제를 수정하고 재검토했다.

## 3. 계약 불일치

검증한 API에서 PRD·Decisions와의 미해결 동작 불일치는 발견하지 않았다. API_SPEC에는 이전 로컬 구현과 제안 단계의 설명이 남아 있으므로 다음 차이는 PRD·Decisions대로 반영했다.

| 엔드포인트 | API_SPEC의 기존 설명 | 실제·PRD·Decisions | 재현·앱 처리 |
| --- | --- | --- | --- |
| `GET /v1/me` | `petInfo`가 객체인 예시·타입 | 반려견 없음은 `null` | 새 개발 계정 조회. `Pet[]`는 빈 배열로 표시 |
| `PUT /v1/me` | 타입에 `id`, `password` 존재 | 해당 필드 전송 시 400. 허용 필드는 `name`, `picture` | 어댑터에서 허용 필드만 전송. 응답 프로필은 `profile` |
| `GET /v1/posts` | 대량 페이지네이션은 후속 합의라는 설명 | 한 페이지 기본 20개, `nextFrom` 지원 | 21개 작성 후 20개·1개 확인. 기존 목록 화면 어댑터가 커서를 순차 조회해 합침 |
| `POST /v1/walk-courses/recommendations` | 기존 정적 `courseFor` 중심 설명 | `latitude`·`longitude`, `source`, 서버가 뒤집은 경유지 | 위치 좌표와 대안 요청. 응답 경유지 순서를 그대로 표시 |
| `GET /v1/shelter-pets` | 외부 연동 미정·예제 데이터 설명 | 키가 있으면 공공 API, 없으면 서버 샘플 | 현재는 키가 없어 샘플 목록. 프런트 샘플로 대체하지 않음 |

명세에는 개별 댓글 삭제 엔드포인트가 없다. 5번은 댓글 작성 후 게시물 삭제로 검증했다. 개별 댓글 삭제까지 요구한다면 백엔드 계약 결정이 필요하다.

## 4. 남아 있는 mock·로컬 데이터

기존 mock은 삭제하지 않고 `EXPO_PUBLIC_USE_MOCK=true`에서만 사용하도록 보존했다.

- `src/modules/rest/my.mock.ts`, `posts.mock.ts`
- `src/modules/careData.mock.ts`, `userData.mock.ts`, `communityData.mock.ts`, `emergencyService.mock.ts`
- `rest/onboarding.ts`의 로컬 온보딩 분기
- `walkData.ts`의 `mockCourseFor()`와 정적 코스
- `emergencyData.ts`의 실종·보호동물 예시는 mock 서비스에서만 사용한다. 체크리스트 항목은 계약상 정적 UI 정의다.
- 개발 메뉴의 예제 데이터 저장도 mock 플래그 뒤로 제한했다.

실제 모드에서 AsyncStorage는 최초 실행 여부와 계정별 검색 이력 등 클라이언트 상태에만 사용한다. 세션 토큰은 SecureStore에 보관한다. 선택한 추천 코스는 산책 시작 시 동일 경로를 전달하기 위해 메모리에 최대 2분 유지하며, 일반 추천은 위치를 다시 조회해 서버에 새 요청을 보낸다.

**서버 샘플:** 공공데이터 키 누락에 따른 `/v1/shelter-pets`의 샘플 fallback은 남아 있다. 이는 백엔드의 문서화된 동작이며 프런트에서 제거할 수 없다.

**기존 로컬 데이터 이관:** 일회성 서버 업로드 마이그레이션은 구현하지 않았다. 업데이트 후 기존 로컬 산책·반려견·게시물은 서버 모드 화면에서 표시되지 않는다. 기존 로컬 저장값을 자동으로 서버 데이터와 합치지 않으며, 탈퇴 시 로컬 앱 데이터도 정리한다.

## 5. 차단 사항·실행 상태

- **Google·Apple 실제 로그인:** 백엔드 OAuth 키가 비어 있다. 유효한 authorize 요청으로 두 공급자 모두 503 설정 오류를 확인했다. Google Client ID·Secret, Apple Services ID와 등록된 공개 HTTPS callback이 필요하다.
- **네이버·카카오 실제 로그인:** 네이티브 SDK→서버 교환 경로는 유지했다. 실제 공급자 계정 로그인과 토큰 검증은 실행하지 않았다. 등록된 앱 키·앱 식별자·URL scheme·공급자 콘솔 설정으로 확인해야 한다. 키 값은 보고·커밋하지 않았다.
- **실제 보호동물:** `PUBLIC_DATA_SERVICE_KEY` 발급·설정이 필요하다. 키가 없으므로 실데이터 정확성과 지역 쿼리 연동은 검증하지 못했다.
- **추가 검증:** 전체 터치 UI E2E, Android·실기기, 위치 거부·GPS 지연·오프라인·권한 오류의 화면별 순회는 남아 있다.
- API는 `0.0.0.0:8080`, 경로 엔진은 `127.0.0.1:8799`, 이번 검증용 Metro는 `8082`에서 실행했다. 기존 `8081` Metro는 건드리지 않았다.
- Expo 구현 전 [정확한 SDK 58 문서](https://docs.expo.dev/versions/v58.0.0/)와 해당 FileSystem·Location 문서를 확인했다.
